# For the Studio chat: revert the right-side mirror

**Please revert the three `mirror = root.endsWith('_R') ? -1 : 1` edits** in the
inlined player rig — in `worldJoints()`, the vertical body's `chain()`, and
`cutMarkup()`. The symptom they were aimed at is real; the mirror is not the
cause, and it breaks the pose library in two ways that are easy to miss on a
single pose.

## Why the mirror is wrong

The rest angles already encode the left/right difference. A pose mirrors by
**swapping `_L`/`_R` and negating** — that is what the pose tool's "Swap L ⇄ R"
button does, and it is the convention every pose in `xquix-poses.json` was
authored in, because the coach dialled each one while watching that renderer.

Measured, rendering each of the coach's left/right pairs and comparing one
against the other flipped horizontally:

| | as shipped | with the mirror |
|---|---|---|
| Ball holding shot | **0 %** of inked pixels differ | 24.7 % |
| Shot blocking | **0 %** | 31.2 % |
| Shot release | **0 %** | 45.9 % |
| Ball protection | **0 %** | 42.8 % |
| Pass release | **0 %** | 45.9 % |

Without the mirror the pairs are pixel-exact mirror images. With it they are not
mirrors at all — the two variants collapse toward the same shape, so a
left-handed player and a right-handed one stop looking different.

It also flattens the freestyle kick. The stroke poses carry `hip_L: -40,
hip_R: +40` — opposite signs, which is what makes the legs scissor. Negating the
right side makes both legs swing the same way and the kick disappears.

## What was actually cutting the forearm off

The SVG's `viewBox` was the **rest pose's** rectangle, and the markup is handed
to the board as an `<img>` src — so anything outside that rectangle is cropped.

Rasterising `Ball holding shot - right arm` and measuring painted pixels: the
figure runs to y = 430 in a box that ends at y = 320. **110 px of forearm, cut
off.** `handOffset` reads the true wrist from the rig, so the ball was still
placed correctly — at a wrist that was no longer drawn. That is exactly the
report: the forearm vanishes and the ball floats clear of it.

The mirror appeared to fix it because negating that pose happened to swing the
arm back inside the box. It fixed the crop by drawing a different pose.

## The fix

`xquix-player-rig.js` now computes the box from the pose (`poseBox`), centred on
the artwork centre so nothing moves or rescales, with `sizeFromRig` reading the
same function so the two cannot drift.

Verified across 274 renders — every pose and every cycle frame, both sexes:
**0 clipped**, 18 distinct box sizes, cache steady at 58, resolve pass 1.1 ms
median. Left/right pairs still 0 % difference.

**Take the whole file** rather than porting the three reverts by hand — it also
carries the generator fix below.

## One thing to know about the file

`xquix-player-rig.js` is generated by `build_board_module.py`, which used to
slice the pose tool's source **by hard-coded line numbers**. Adding the limb/side
selectors to the tool shifted those lines, so a rebuild would have spliced the
wrong text into a 73 KB module. It now anchors on the declarations themselves.

This is also why the rig and the resolver were meant to stay as separate files:
inlining them into `index.html` means edits to them land in a file this side
cannot see. Either is fine — but if they stay inlined, changes to that code need
relaying back, exactly as you did here.
